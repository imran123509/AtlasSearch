# BM25

The lexical relevance function. Stage L0 of the [ranking cascade](RANKING.md), and the
baseline everything else is measured against.

Related: [RANKING](RANKING.md) · [INVERTED-INDEX](INVERTED-INDEX.md) · [TOKENIZATION](TOKENIZATION.md)

---

## The formula

```
                     f(t,d) · (k₁ + 1)
BM25(q,d) = Σ IDF(t) · ─────────────────────────────────
            t∈q        f(t,d) + k₁ · (1 − b + b · |d|/avgdl)


            ⎛  N − df(t) + 0.5      ⎞
IDF(t) = ln ⎜ ───────────────── + 1 ⎟
            ⎝   df(t) + 0.5         ⎠
```

| Symbol | Meaning |
| --- | --- |
| `f(t,d)` | Frequency of term `t` in document `d` |
| `df(t)` | Number of documents containing `t` |
| `N` | Total documents in the collection |
| `|d|` | Document length in tokens |
| `avgdl` | Average document length |
| `k₁` | Term-frequency saturation, default **1.2** |
| `b` | Length normalisation, default **0.75** |

---

## What each part is doing

### IDF — rare terms carry more information

A term in 90% of documents contributes almost nothing; a term in 0.001% dominates the score.
This is why **stopword removal is unnecessary** ([TOKENIZATION](TOKENIZATION.md)) — IDF
already handles it, and it does so continuously rather than with a hard cutoff.

The `+1` inside the log keeps IDF non-negative for terms appearing in more than half the
corpus. Without it, common terms get *negative* weight and a document is penalised for
containing "the", which is not what anyone wants.

### Saturation (`k₁`) — the key improvement over TF-IDF

```
raw tf:    1 → 1.0   5 → 5.0   50 → 50.0   500 → 500.0
BM25 tf:   1 → 1.0   5 → 2.6   50 → 3.5    500 → 3.6    (k₁ = 1.2)
```

The 500th occurrence adds almost nothing. This is both linguistically right — a document
mentioning "jaguar" 500 times is not 100× more about jaguars than one mentioning it 5 times —
and the **primary defence against keyword-stuffing spam**.

| `k₁` | Behaviour |
| --- | --- |
| 0 | Binary. Term presence only, frequency ignored. |
| 1.2 | Default. Saturates quickly. |
| 2.0+ | Slower saturation, closer to raw TF. More spam-exposed. |

### Length normalisation (`b`) — fairness across lengths

Long documents contain more terms by accident. Without normalisation they always win.

| `b` | Behaviour |
| --- | --- |
| 0 | No normalisation. Long documents dominate. |
| 0.75 | Default. |
| 1.0 | Full normalisation. Over-penalises long, genuinely comprehensive documents. |

Use the **post-boilerplate** length ([HTML-PARSER](HTML-PARSER.md)). If navigation and footer
text count toward `|d|`, every page on a site is inflated by the same constant and
normalisation punishes the ones with real content.

## BM25F — fielded scoring

Web documents have structure. A term in the `<title>` means more than the same term in
paragraph 40.

The critical detail: **combine frequencies across fields *before* saturation, not after.**

```
❌ WRONG:  score = Σ_fields w_f · BM25(field_f)
              → saturation applied per field, then summed
              → a term can be stuffed once per field to bypass saturation

✅ RIGHT:  f̃(t,d) = Σ_fields w_f · f(t, d.field_f) / (1 − b_f + b_f · len_f/avglen_f)

                            f̃(t,d) · (k₁ + 1)
           score = Σ IDF(t) · ──────────────────
                   t∈q         f̃(t,d) + k₁
```

Weighting per field, then one saturation over the combined frequency.

### Field weights

| Field | Weight | Notes |
| --- | --- | --- |
| `anchors` | 10.0 | Often the best description of a document. Also the most spammed. |
| `title` | 8.0 | Strong, but heavily optimised by SEO |
| `headings` | 3.0 | |
| `url_text` | 2.5 | Tokenised path segments |
| `body` | 1.0 | Baseline |
| `meta_description` | 0.5 | Frequently spam |

Anchor weight is the highest and the most dangerous — it is the field an attacker controls
from *outside* your document. Cap the contribution from any single source domain, or a
handful of coordinated sites can rank you for anything ("Google bombing").

## Practical concerns

### Corpus statistics must be global

`N`, `df(t)`, and `avgdl` are corpus-wide. With [document-partitioned shards](SHARDING.md),
each shard sees only its own slice — and shard-local IDF produces **inconsistent scores across
shards**, so the merged top-k at the root is wrong.

Two options:

1. **Broadcast global stats** to all shards with each index generation. Adds a synchronisation
   point; correct.
2. **Accept the approximation.** With random document assignment and large shards, local `df`
   is a good estimator of global `df`. Error is small and shrinks with shard size.

Take option 2 for uniform shards, option 1 when tiering makes shards non-uniform — which it
does, since [tier 0](SHARDING.md) is deliberately a biased sample of high-quality documents
and its local statistics are systematically wrong.

### Tuning

Grid-search `k₁ ∈ [0.5, 2.0]`, `b ∈ [0.3, 1.0]` against NDCG on a rated set. Expect modest
gains — BM25 is not very sensitive to these, and time is better spent on **field weights**,
**proximity**, and the **static rank prior**, which move NDCG far more.

### Combining with static rank

```
final_L0 = BM25F(q,d) + α · log(1 + pagerank(d)) + β · quality(d)
```

Additive in log space, not multiplicative — a multiplicative prior lets one high-authority
document with a weak textual match beat a perfect match on a smaller site, which is exactly
the "big sites always win" failure mode.

## Target vs Build

| | Target | Build |
| --- | --- | --- |
| Implementation | Custom, SIMD, block-max bounds precomputed | Lucene `BM25Similarity` |
| Fielded | Own BM25F | `multi_match` `cross_fields` (approximates BM25F) or a custom `Similarity` |
| Stats | Broadcast global for tiered shards | Single shard — no problem |
| Static rank | In the posting order + `rank_feature` | `rank_feature` field with `log` function |

Note: OpenSearch's `most_fields` mode sums per-field scores — the ❌ pattern above. Use
`cross_fields`, which blends statistics across fields before scoring.

## Failure modes

| Failure | Consequence | Mitigation |
| --- | --- | --- |
| Per-field saturation (`most_fields`) | Keyword stuffing bypasses saturation | Combine frequencies before saturation |
| Boilerplate counted in `\|d\|` | Length normalisation punishes real content | Use post-extraction length |
| Shard-local IDF on tiered shards | Inconsistent scores; wrong merge order | Broadcast global stats for non-uniform shards |
| Uncapped anchor text | Off-page attackers rank you for anything | Cap per source domain; require domain diversity |
| `k₁` too high | Keyword stuffing works | Keep ≤1.5; monitor top-term-frequency distribution of top results |
| `avgdl` stale after a large crawl | Scores drift across generations | Recompute per generation, ship in the manifest |
